NewsMuncher Phase 4B — universal comedy vocabulary foundation
Date: 2026-10-10

Scope and safety
================

Phase 4B adds a static, typed catalogue, an offline deterministic selector and
validation/audit tooling. No application module imports the catalogue and no
live prompt, CSV, registry, cooldown, claim, database or media path changed.
The work performed zero network, database or provider operations.

Architecture
============

`newsmuncher/resources/vocabulary/comedy_vocabulary_catalogue.json` is a
versioned catalogue (schema 1.0, catalogue phase4b-1). Each ingredient has a
stable family-scoped ID; display text; category and subtype; category-specific
grammar; semantic class; compatible mechanisms; humour metadata; familiarity;
source/licence attribution; editorial flags; and an explicit approval status.
The companion `catalogue.schema.json` documents the portable resource shape.

`newsmuncher/services/vocabulary_catalogue.py` loads and validates the static
resource and offers deterministic seeded selection. Selection prioritises
ingredients outside a supplied recent-ID window, balances semantic classes and
common/unusual/obscure familiarity bands, honours mechanism and grammatical
role constraints, and keeps machine-checked content visibly distinct. It uses
preloaded lists only: no database, registry or network dependency.

`scripts/diagnostics/build_vocabulary_catalogue.py` reproducibly builds the
snapshot from existing approved structured resources plus explicitly marked
Phase 4A samples. It does not download or silently scrape data.

Provenance and licensing
========================

All entries in this Phase 4B snapshot are repository-local. Their source IDs
are `newsmuncher-curated`, `phase4a-editorial-seed` or `legacy-local-filter`.
They deliberately carry `INTERNAL-UNVERIFIED`, with attribution text warning
that ownership/licensing must be resolved before external redistribution.
No external dataset has been copied into the repository.

Future imports should use the Phase 4A recommendations only after retaining
source-specific identity and notices: Wikidata CC0; Open English WordNet CC BY
4.0 plus the Princeton notice; OS Open Names OGL 3.0; GeoNames CC BY 4.0; and
release-specific ONS/OGL notices. GBIF must be admitted dataset by dataset.
Wiktionary remains excluded until a deliberate CC BY-SA/GFDL compatibility
decision is made.

Validation and quality gate
===========================

The validator checks required fields, stable IDs, exact and simple inflectional
near-duplicates, malformed text, grammatical descriptor roles, source and
licence support, blocked discriminatory terms, trademark/real-person flags,
false editorial approval, unsupported obscurity and semantic concentration.
Automated validation does not promote an entry to editorially reviewed.

The generated catalogue has zero validation errors. Three warnings remain:
animals have only a coarse `animal` class; 308 legacy object candidates remain
`unclassified_object`; and the small place bank is dominated by fictional
morphology. These warnings block any claim that Phase 4B is production-ready.

Phase 4B removes all short-window repetition for the four sufficiently broad
families. Its lower lifetime descriptor/slang/place diversity is deliberate:
Phase 4A counted unreviewed flat CSV content, including unsafe, malformed and
grammatically incompatible entries. Phase 4B refuses to present that raw
quantity as approved vocabulary. Slang and places clearly need licensed,
human-reviewed expansion before integration.

The audit covered 36 descriptor semantic classes, 15 name semantic classes and
six object classes. Names spanned six component/construction subtypes; places
spanned three. Runtime was 5,189.12 ms with 6,241,821 peak traced bytes. It made
zero database, network and provider operations. Performance is adequate for an
offline build/audit; live integration should load once and batch history reads.

Remaining gaps and risks
========================

The aspirational ranges remain far away: 134 versus 1,000–5,000 animals; 508
versus 5,000–20,000 objects; 708 descriptor ingredients versus several
thousand; 494 name ingredients versus several thousand; 30 safe slang units
and 58 place units versus several thousand each. Counts must grow through
licensed acquisition and editorial review, not by relabelling legacy CSVs.

Animals require taxonomic classes, stable species IDs and recognisability
notes. Legacy objects need affordances and human review. Name samples need
real-person collision review. Slang needs register, meaning, region, target and
explicitness fields. Place parts need morphology compatibility rules so suffix
and feature ingredients become plausible fictional constructions. Ingredient
selection alone does not guarantee comedy; generators still need compatible
templates and premise-level memory.

Recommended staged integration
==============================

1. Resolve repository-local licensing and complete review of current machine-
   checked samples; rejected entries remain recorded rather than silently used.
2. Build separate, versioned importers for Wikidata/OEWN and licensed geography
   sources. Store upstream IDs, exact licence/version and transformation notes.
3. Add taxonomic/object affordance/place morphology metadata and conduct a
   sampled human review before increasing catalogue versions.
4. Shadow the selector beside each current generator and compare grammar,
   comedy and repetition without adding prompt content or claims.
5. Integrate one family at a time behind configuration, retaining existing
   registries, exact accepted-use handling and legacy fallback. Start with
   animals or objects; defer slang and places until their review coverage is
   materially larger.
