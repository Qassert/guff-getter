LIVE PIPELINE FINDINGS
1. `load_random_words(10)` draws ten unclaimed values from `adverbs.csv` through the existing shared word-bag system. Source filtering then removes literal source collisions.
2. The ten values are shuffled and split across `{adverb_words1}`, `{adverb_words2}` and `{adverb_words3}`. The rewrite prompt labels the bank “Adverbs/absurd descriptors” and says grammar/pluralisation may be altered.
3. Source DESCRIPTION placeholders are currently assigned from `adverbs` and adjective/adverb-shaped `slang`. The replacement guidance describes every descriptor as needing adjective/adverb inflection; it has no representation for predicate, post-noun, behavioural or clause forms.
4. The first rewrite call receives all banks. The second copy-edit call receives only pass-one title/body, so it cannot see candidate metadata. Exact supplied values found in the final accepted title/body are permanently claimed from the five legacy claim banks.
5. Generated comedy concepts and invented names are supplied as overrides before this prompt is built. Concepts use a separate lease/cooldown collection and are excluded from permanent CSV claims; invented names also have their own temporary lease/cooldown lifecycle.
6. Source masking protects entities, objects, phrases and descriptions before the prompt. Full generated-descriptor replacement can fit safely at the existing ten-value override point, but role-aware assignment should not pretend every generated phrase can directly replace a DESCRIPTION placeholder.

SHADOW DESIGN
- The live code and prompt are unchanged. The shadow module fills the existing ten descriptor slots only in an offline prompt preview.
- Generated values carry phrase, role, insertion rule, category, intensity, mechanism, word count, subject and generator version.
- The preview annotates every generated value with role and insertion guidance, then adds four concise optional-use rules: use roughly two to four; respect roles; mix short/developed forms and mechanisms; never concatenate descriptors.
- Full ten-item slates retain exact 7/3 cheeky/absurd and 3/5/2 mild/properly-absurd/unhinged allocations. Slate selection prefers new roles first, then new mechanisms and short forms. Across the ten reviewed full slates, every slate contained all six roles, no repeated subject, and normally eight or nine descriptors of eight words or fewer.
- The metadata is guidance for sentence restructuring, not a demand that every descriptor fill a masked adjective slot. A future live integration should allow the model to select a fitting descriptor elsewhere in the same sentence when a direct placeholder replacement would be ungrammatical.

STRATEGY COMPARISON
A — ten generated, zero CSV
- Best grammatical information and comic variety; exact ten-slot replacement; no permanent descriptor claims.
- Ten-slate average estimated prompt increase: +430 tokens. A representative split is +307 tokens from annotated candidates and +119 from optional-use guidance (character-count / 4 estimate).
- All six roles appeared in every audited slate. Mechanism repetition was normally limited to the two `secret_history` forms needed to cover behavioural and post-noun roles.
- Main risk: the live prompt already contains twenty concepts, ten names, slang and places. The 2–4 optional-use rule and short-form preference are necessary to prevent joke congestion.

B — seven generated, three CSV
- Lower average increase: +337 estimated tokens. Retains permanent-claim complexity for three legacy values and mixes role-aware phrases with untyped CSV material.
- Provides less clean grammar semantics and two tracking systems for one visible bank. It is useful as a rollback experiment, not the clearest destination.

C — six generated, four CSV
- Lowest average increase: +315 estimated tokens and least risk of descriptor density.
- Often covers five or six roles but sacrifices mechanism breadth. It retains the same mixed tracking and grammatical ambiguity as B.

RECOMMENDATION FOR PHASE 3D
Use Strategy A behind a configuration switch with legacy mode preserving the original CSV path. Full replacement is viable because each slate is role-diverse, subject-diverse and mostly concise, while the prompt explicitly requests only two to four natural uses. Do not assign generated predicate/clause forms directly to DESCRIPTION placeholders. Supply them as role-labelled optional ingredients and let surrounding sentence structure change naturally. Keep the guidance concise in production; the verbose annotation used here is deliberately audit-friendly and can be compressed to role tags plus one shared role key.

USAGE TRACKING / COOLDOWN DESIGN
- Use a dedicated generated-descriptor usage collection; do not alter existing permanent word claims or `adverbs.csv`.
- Key deterministic selection and leases with the newly allocated rewrite UUID (plus pet/owner scope where appropriate), never the durable browser draft session. A genuine retry returns its saved slate; a new MUNGE from the same source gets a fresh expanded generator seed.
- Generate a bounded rewrite-specific queue of at least 500 candidates, rather than revisiting a small global fixed pool. Select ten unique phrases and subjects while excluding active leases and cooldown records.
- Store normalized phrase, subject, grammatical role, generator version, offered-by attempt, offer expiry, last-used timestamp, use count and accepted rewrite ID.
- Use atomic phrase leases and also exclude subjects held by concurrent live leases. Release unused offers after successful completion and all offers after failed rewriting. Expired leases become naturally eligible.
- Apply cooldown only to exact phrase matches in the final accepted title/body. Exact matching is conservative and misses inflections or paraphrases; it is preferable to false claims. A later structured provider response or carefully tested local lemma matcher could improve attribution without another provider call.
- Tracking failure after a successfully persisted paid rewrite should be logged and released without discarding the creation, matching existing name/concept safety behaviour.
- The offline registry successfully handled stable retries, two concurrent disjoint slates, failure release, expiry, exact-use cooldown, paraphrase non-claiming, and eight fully accepted ten-item rounds followed by a ninth fresh rewrite-specific slate.

COST / COMPATIBILITY
- No additional provider request is required. Strategy A increases prompt input only; the representative estimate is about 426 tokens, while the ten-slate average is 430.
- Historical creations need no migration. Legacy mode continues to load and permanently claim `adverbs.csv` exactly as today.
- The existing copy-edit pass, concepts, invented names, source masking, titles and downstream media remain compatible because descriptors affect only first-pass prompt ingredients.

RISKS TO CARRY INTO PHASE 3D
- Exact accepted-use matching misses inflected or paraphrased phrases.
- Audit annotations are verbose; production formatting should be compressed without losing role semantics.
- Full replacement increases an already rich prompt. Manual mocked/live editorial review should confirm that the 2–4-use rule is obeyed before making generated mode the default.
- A predicate or clause must never be forced into an adjective-only placeholder. Integration tests must inspect the final prompt and tracking contenders, not merely the generated slate.
